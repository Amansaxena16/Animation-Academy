# Deploying Animation Academy

The website runs on **Vercel**, the API and database on **Render**, and uploaded photos in a **Cloudflare R2** bucket. Everything the hosts need is in the repo (`render.yaml`, `frontend/vercel.json`, `backend/Dockerfile`, `.github/workflows/ci.yml`). This guide covers the steps done in their dashboards.

```
Visitor ──► Vercel: the website (Next.js)
              │  /api/v1/* is passed through ──► Render: the API (Django + gunicorn) ──► Render Postgres
              │                                             │
              └──────────── images ◄── Cloudflare R2 (private bucket, signed links) ◄──┘
```

**Why the website passes `/api/v1` through:** the browser only ever talks to the website's own address. The login cookies are therefore first-party, and they work on `*.vercel.app` before you own a domain, with no cross-site cookie settings to get wrong. The API is still reachable directly at its Render address. The Django admin is served there, at `/django-admin/`.

## What it costs

Check each host's pricing page. Prices change, so none are quoted here.

| Service | Plan | Why this plan |
|---|---|---|
| Render web service `aa-api` | Starter | The free plan sleeps after 15 minutes, so the first visitor waits almost a minute. Starter also gives you the Shell and the pre-deploy migrate step. |
| Render Postgres `aa-db` | Basic (smallest) | Free databases are deleted after 30 days. Paid ones have point-in-time recovery. |
| Render cron `aa-flush-tokens` | Starter | Billed by the minute; it runs for a few seconds each night. |
| Vercel | **Pro** | Vercel's free Hobby plan is for personal, non-commercial sites. An institute's website is commercial. |
| Cloudflare R2 | Free tier | 10 GB is far more than student photos need. |

## 1. Storage bucket (Cloudflare R2)

1. Cloudflare dashboard → **R2** → **Create bucket**. Name it `animation-academy-media`, location Asia-Pacific. Leave **public access off**.
2. **R2 → Manage API tokens → Create API token**. Choose *Object Read & Write*, applied to that bucket only. Note these values:
   - **Access Key ID** → `S3_ACCESS_KEY_ID`
   - **Secret Access Key** → `S3_SECRET_ACCESS_KEY` (shown once)
   - **S3 endpoint**, `https://<account-id>.r2.cloudflarestorage.com` → `S3_ENDPOINT_URL`
3. Bucket → **Settings → CORS policy**: not needed, because images are loaded with plain `<img>` tags.

## 2. Pick the website address

Until you buy a domain, the site lives at `https://<project>.vercel.app`. Choose the project name now, for example `animation-academy`. That gives `https://animation-academy.vercel.app`, which is used as **`SITE`** below. If the name is taken, Vercel adds a suffix; use whatever address Vercel shows you.

Generate one shared secret for instant refresh (it goes into both hosts):

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(32))"
```

## 3. API and database (Render)

1. Render dashboard → **New → Blueprint** → connect GitHub → pick `Amansaxena16/Animation-Academy`. Render reads `render.yaml` and proposes `aa-db`, `aa-api` and `aa-flush-tokens`.
2. Fill in the values it asks for:

   | Variable | Value |
   |---|---|
   | `PUBLIC_SITE_URL` | `SITE` (printed on certificates as the verification link) |
   | `CSRF_TRUSTED_ORIGINS` | `SITE` |
   | `CORS_ALLOWED_ORIGINS` | `SITE` |
   | `FRONTEND_REVALIDATE_URL` | `SITE/api/revalidate` |
   | `REVALIDATE_SECRET` | the secret from step 2 |
   | `S3_BUCKET` | `animation-academy-media` |
   | `S3_ENDPOINT_URL`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | from step 1 |

   `DJANGO_SECRET_KEY` is generated by Render, and `DATABASE_URL` is linked to the database automatically.
3. **Apply.** The first build takes a few minutes. When it's live, `https://aa-api.onrender.com/healthz` shows `ok`. If Render gave the service a different address, use that one everywhere below.
4. **One-time setup**, from `aa-api` → **Shell**:

   ```bash
   python manage.py seed_courses     # the 9 prospectus courses
   python manage.py seed_content     # site settings and sample announcements
   python manage.py createsuperuser  # the office's admin login (email + password)
   ```

   ⚠ Run `seed_courses` **only this once**. It resets every course to the prospectus text and fees, which would undo the office's edits.
5. If the Blueprint rejects a plan name (Render renames plans now and then), pick the smallest paid plan in the dashboard.

Optional: email. Add `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD` and `DEFAULT_FROM_EMAIL` to `aa-api` when the institute has an SMTP account. Nothing sends email yet.

## 4. Website (Vercel)

1. Vercel → **Add New → Project** → import `Amansaxena16/Animation-Academy`.
2. **Root Directory: `frontend`**. The framework (Next.js) is detected automatically. Use the project name from step 2.
3. Environment variables (Production):

   | Variable | Value |
   |---|---|
   | `NEXT_PUBLIC_API_URL` | `/api/v1` |
   | `API_INTERNAL_URL` | `https://aa-api.onrender.com/api/v1` |
   | `NEXT_PUBLIC_SITE_URL` | `SITE` |
   | `NEXT_PUBLIC_MEDIA_ORIGIN` | the R2 endpoint, `https://<account-id>.r2.cloudflarestorage.com` |
   | `REVALIDATE_SECRET` | the same secret as on Render |

4. **Deploy.** The site's server functions run in Singapore (`sin1`, from `vercel.json`), next to the API.

The `NEXT_PUBLIC_*` values and `API_INTERNAL_URL` are built into the site. After changing any of them, redeploy: **Deployments → ⋯ → Redeploy**.

## 5. Check it before telling anyone

Open `SITE` in a private window:

1. The home page and courses show; `/sitemap.xml` lists the courses.
2. `SITE/login` → log in with the admin from step 3.4 → you land in the admin console.
3. In **Settings**, fill in the institute details. Change a course's fee, open its public page, and the new fee shows straight away (this proves instant refresh works).
4. Apply for a course on `/admission` with a test email. In the console, **Approve** it, then **Complete** it, then download the PDF. Open the certificate code at `SITE/verify`. Upload a photo on the test student's profile and check that it shows in the console.
5. Delete the test student: `https://aa-api.onrender.com/django-admin/` → Students.
6. **Check the rate limits:** on `/login`, enter a wrong password 11 times in a minute. The 11th attempt must say to try again later. Then log in from a phone on mobile data; it must work. If the limit never triggers, or blocks everyone at once, set `TRUSTED_PROXY_COUNT=2` on `aa-api` (it tells Django how many proxies to skip in `X-Forwarded-For`) and check again.
7. Check the security headers at https://securityheaders.com (expect A or better).

Real content still to fill in before launch: the Director's name (printed on certificates), the home page numbers, course photos, and the prospectus spellings. See PROJECT_GUIDE §13.

## Everyday updates

- Push or merge to `main`, and GitHub CI runs: backend tests, frontend build, and the browser tests.
- **Vercel** deploys the website straight away.
- **Render** deploys the API only after CI passes (`autoDeployTrigger: checksPass`), and runs database migrations before switching over.
- The website can therefore go live a few minutes before the API. Keep API changes backwards-compatible: add new fields first, and remove old ones in a later release.

## Backups

- **Render** keeps point-in-time recovery for paid databases (Dashboard → `aa-db` → Recovery). The retention period depends on the workspace plan.
- **Also keep your own copy** each month, on the office computer:

  ```bash
  pg_dump "<External Database URL from aa-db → Connect>" -Fc -f aa-$(date +%F).dump
  ```

  It holds students' personal details. Keep it somewhere private, and **never put it in the GitHub repo**, which is public.
- Restore into a new database with `pg_restore -d "<new database URL>" --no-owner aa-YYYY-MM-DD.dump`. Try it once, so you know it works.
- Photos live in R2 and aren't part of the database dump. R2 is durable storage; for a second copy, use `rclone copy` from the bucket.

## When you buy a domain

For example, `animationacademy.in`:

1. Vercel → Project → **Domains** → add `animationacademy.in` and `www.animationacademy.in`, and follow the DNS instructions. Vercel issues the HTTPS certificate.
2. Change `SITE` to `https://animationacademy.in` everywhere:
   - Vercel: `NEXT_PUBLIC_SITE_URL`, then redeploy
   - Render: `PUBLIC_SITE_URL`, `CSRF_TRUSTED_ORIGINS`, `CORS_ALLOWED_ORIGINS`, `FRONTEND_REVALIDATE_URL`
3. Certificates issued earlier print the old `vercel.app` link. It keeps working, because Vercel serves the project on both addresses.
4. Optional: `api.animationacademy.in` → Render (`aa-api` → Settings → Custom Domains), then set `API_INTERNAL_URL` to it. This only makes the Django admin's address tidier.
5. After a few months on HTTPS only, you may set `SECURE_HSTS_PRELOAD=True` and submit the domain to hstspreload.org. It is hard to undo.

## If something is wrong

| Symptom | Likely cause |
|---|---|
| The website's `/api/v1/...` gives 404 or 502 | `API_INTERNAL_URL` is wrong, or the API is down (`/healthz`). Redeploy Vercel after fixing it. |
| Build fails: "API_INTERNAL_URL must give the API's full URL" | `NEXT_PUBLIC_API_URL` is `/api/v1` but `API_INTERNAL_URL` is missing. |
| Logging in returns to the login page | The browser blocked the cookie. The site must be opened over `https://`. Check `NEXT_PUBLIC_API_URL` is `/api/v1`. |
| Photos and course images don't show | `NEXT_PUBLIC_MEDIA_ORIGIN` doesn't match the image links. Open an image link and copy its origin. |
| Admin edits take 5 minutes to show | `REVALIDATE_SECRET` differs between the hosts, or `FRONTEND_REVALIDATE_URL` is wrong. |
| Uploaded photos vanish after a deploy | `S3_BUCKET` isn't set, so files went to the server's disk, which each deploy wipes. |
| Django admin says "CSRF verification failed" | Add the address you're using to `CSRF_TRUSTED_ORIGINS`. |
